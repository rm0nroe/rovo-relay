What you can do

Ask, follow up and retrieve answers from your coding task.

Approve your Chrome connection

Optional macOS helper for the relay’s own approval prompt.

With explicit authorization, --approve-chrome-prompt and a verified Chrome port let the bundled helper click Allow for this connection. It refuses existing debugging prompts or other clients and stops on ambiguity. Manual approval remains the default; this does not grant persistent permission or approve Rovo actions. Native dependencies and terminal permissions are required. Keep other automation and pointer input paused during attachment.

Keep the conversation going

Follow-ups find the right chat, even after a restart.

The first ask starts a chat. Later asks with the same site, session and account verify and continue it. Use --new for a separate task or --chat for an observed conversation. Automatic continuity is direct CLI only. A direct follow-up in the same connection can skip the chat picker when the open conversation still passes every identity and history check. After a restart, intervening operation or changed reuse evidence, the normal picker path applies.

Leave your tabs alone

Uses its own tab and waits through sign-in redirects.

One approved connection stays open across commands. The CLI checks the account and prepares its own tab, including the overflow-menu launcher in narrow windows. During an Atlassian sign-in redirect it waits for Jira without interacting with the identity page. If readiness cannot be established, it stops without refreshing or sending. User tabs and drafts stay intact; a closed owned tab is replaced only after delivery guards pass.

Get an answer and a next step

Copilot gets a bounded result with one explicit action.

next tells the agent to proceed, inspect continuity, use an eligible Playwright MCP browser fallback, fix rejected input, or stop. Browser failures say stop. The result also includes phase timings; a completed answer is never resent.

Check that the answer is complete

Reads the answer and generation state together.

Each check reads the response, generation state and matching user turn in one snapshot. The relay waits for evidence that this question started and finished; duplicate status regions stop the operation. This reduces browser reads but does not speed up Rovo’s generation.

Bring images and conversation context

Ask with PNGs, list chats and export their visible text.

The CLI supports PNG attachments, a GitHub chat-source filter, loaded conversation listing and text export. A source filter narrows the request; it does not grant additional access or guarantee retrieval.

Stop safely when delivery is unclear

No blind retries, duplicate sends or silent chat switches.

Uncertain delivery blocks the site across sessions and transports. Missing or changed history stops automatic follow-up; a completed answer is kept even if chat capture fails. Click errors return fixed diagnostic labels without page text, URLs or raw browser logs. An unacknowledged click is identified separately from a click waiting for navigation. Neither authorizes a resend.

Why build Rovo Relay?

Rovo Relay lets Copilot ask a question in Rovo Chat, continue that conversation and use the answer in a coding task. It connects through your signed-in Chrome browser, with your approval.

Ask Rovo to do the work

Rovo receives a question and produces an answer. Rovo Relay uses the chat interface; Atlassian A2A offers an official agent connection.

Give Copilot data tools

Copilot retrieves records and decides what to do with them. Atlassian MCP, Teamwork Graph CLI and Jira REST serve this role.

Use another coding agent

Rovo Dev handles coding work in its own agent workflow. It runs through ACLI, Atlassian’s command-line application.

When to use the browser bridge

Choose Rovo Relay when you need to work in Rovo Chat through an approved browser connection. It tracks the conversation, limits the returned text and blocks uncertain resubmissions.

Use an official interface when it covers the task: REST for focused Jira retrieval; MCP or Teamwork Graph CLI for broader data tools; A2A for delegation to Rovo. The browser bridge needs maintenance when the UI changes. The optional macOS helper can click its own approval prompt, but Chrome access still requires your authorization.

What an API token makes possible

A scoped API token lets an integration search Jira and read selected issue fields through REST. The calling agent interprets the results. MCP token access has separate requirements.

MCP needs organization approval

An organization admin must enable MCP token authentication. Access also requires MCP scopes, permitted tool groups and permission to read the data. A Jira REST token alone is insufficient. OAuth is another option and is required for code tools. MCP access requirements ↗

A token does not continue a Rovo chat

REST and MCP give the calling agent data tools. A2A delegates tasks to Rovo through OAuth. Neither data-tool access nor an A2A task conversation implies continuity with an existing browser chat.
